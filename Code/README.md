## pif-webapp

Start with its [README](pif-webapp/README.md). In short:

| Page | What for | Who |
|---|---|---|
| `/` | The visitor app: map, where you are, stories as pins, start a journey and listen | Anyone, on a phone |
| `/debug` | Simulated rides, showcase setup ("Mark here"), pet test panel, simulated pet screen | The team |
| `/lab` | Pet screen lab: screen designs in the pet's own fonts, layers, live mirror to the real screen, clips with sound | The team, desktop Chrome/Edge + pet on USB |
| `/media` | Pet media: convert videos/animations, put them on the pet's SD card, play and tune them | The team, desktop Chrome/Edge + pet on USB |

```sh
cd pif-webapp
npm install
npm run dev          # http://localhost:5173
npm run dev:phone    # HTTPS on your Wi-Fi, for real GPS on a phone
npm run build        # type-check and build into dist/ (any static HTTPS host)
```

### The pet's firmware

`firmware/pet_story_player/` is the full firmware:

| File | Does |
|---|---|
| `pet_story_player.ino` | Bluetooth LE peripheral, story playback from SD (WAV), the audio task, moods, buttons, sleep, Serial commands (`help`) |
| `pet_screen.h` | Everything on the screen (ST7789 TFT, or an SH1106 OLED test build), plus "lab mode" for live frames over USB |
| `pet_lab.h` | Clips from the lab: frames and sound received into PSRAM, played in sync |
| `pet_media.h` | Videos from the SD card: MJPEG + WAV, the sound as the clock |
| `faces.h` | The face animations (generated by `scripts/convert-faces.mjs`) |

Build: Arduino IDE, **ESP32 Wrover Module**, **Huge APP** partition. Libraries and the step-by-
step bring-up (Bluetooth test, speaker, display, story player…) are in
[firmware/README.md](pif-webapp/firmware/README.md); every wire is in
[firmware/WIRING.md](pif-webapp/firmware/WIRING.md).

The other sketches in `firmware/` are the single-purpose tests we built the pet up from (one
part at a time, each proven before the next): `pet_ble_test`, `speaker_test`,
`bt_speaker_test`, `display_gps_test`, `display_check`, `oled_check`, `key_check`.

## Local_Host (TFT Web Lab)

A self-contained tool for trying things on the 2.4" screen from a browser, without
recompiling: fill colours, a colour test and test pattern, text in several fonts and sizes,
and images (with a gallery that plays as a slideshow), plus a raw console.

1. Upload `Local_Host/TftBridge/Local_Host.ino` to the board (**ESP32 Dev Module**; libraries:
   Adafruit GFX, Adafruit ST7735 and ST7789).
2. Double-click `Local_Host/start.bat` (needs Node.js). It serves the page at
   `http://localhost:8000` and opens it.
3. In Chrome or Edge: **Connect board**, then use the Display, Text and Images tabs.

Its serial protocol (460800 baud, one text command per line: `PING`, `INFO`, `ROT`, `INVERT`,
`FILL`, `TESTPAT`, `TEXT`, `IMG`, `IMGR`) is documented at the top of the sketch. Note its wiring
comment (DC on IO21, RST on IO22) is from before the display moved; the current pet wiring is
in [firmware/WIRING.md](pif-webapp/firmware/WIRING.md) (DC on IO22, RST to EN). Its notes also say
this panel needs colour inversion **on**.

`pif-webapp`'s `/lab` grew out of the same idea and works with the main firmware
(`pet_story_player`), so the pet doesn't need re-flashing to switch between the lab and stories.
